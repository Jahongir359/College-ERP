Edit files under `backend/`; never delete or replace the symlinks.

## Commands (run from `backend/`; CI runs the same in `.github/workflows/django.yml`)

```bash
python -m ruff check .              # CI pins ruff==0.15.15
python -m ruff format --check .
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py collectstatic --noinput --dry-run -v 0
python manage.py compilemessages    # web translations (uz/ru); needs gettext, tests need it
python manage.py test               # 562 tests passing as of 2026-10-31
```

Backend tests live in `backend/main_app/tests/` (one file per topic). App tests live in
`mobile/iceberg_app/test/`. New School code goes in new modules (e.g. `school_views.py`), not in the
already large `hod_views.py` or `api/admin_views.py`.

All must pass before a commit. Django CI (`.github/workflows/django.yml`) runs them when backend files
change. For the app, Flutter CI (`.github/workflows/flutter.yml`, Flutter 3.47.7) runs
`flutter analyze --no-fatal-infos`, `flutter test` and `flutter build web --release --base-href /app/`
when `mobile/iceberg_app/` changes; run the same locally where Flutter is installed.

## Domain rules

- Roles: `CustomUser.user_type` `"1"` Admin/HOD, `"2"` Staff/Teacher, `"3"` Student. `"4"` Parent
  (linked to children through `ParentChild`; uses the app only).
- **Where each role works (owner decision D15, 2026-10-26):** admins use the Django web ERP; teachers,
  students and parents use the Flutter app (phone, or the browser at `/app/`). Build new School
  features in the API + app, and admin screens only on the web. The Django student and teacher pages
  are frozen: fix bugs, add nothing new.
- Branch-scoped access lives **only** in `backend/main_app/branching.py`. Never filter by branch
  inline in views, forms or the API.
- Super admins see all branches; branch admins see `Admin.branches`; teachers see groups they teach;
  students see their own data.
- `/` and `/login/` are the ERP login page. Don't repurpose `/`.
- `main_app/middleware.py` `LoginCheckMiddleWare` redirects anonymous users to login unless the
  path is on its allow-list — any new public page must be added there (with a test).
- Every user-facing string must exist in Uzbek, Russian and English (web templates and
  `mobile/iceberg_app/lib/core/i18n/strings.dart`). On the web use `{% translate %}` / `gettext`
  and add the uz and ru text to `backend/locale/*/LC_MESSAGES/django.po` (see plan task P3.0).

## Working conventions

- Prefer small, additive changes. Migrations: additive only, generated with `makemigrations`.
- Match the surrounding code style; don't reformat files you aren't changing.
- Don't change existing Learning Center copy (texts); brand work goes through the brand layer
  described in the plan. Exception (plan decision D19, 2026-11-01, owner): the admin web shell follows
  the plan mockups in both brands, so Study Center admin colors move to the mockup palette (navy
  #103A57/#07233A, lime #CDF163, ice #38BDF0).
- Commit messages follow `type(scope): summary`, e.g. `feat(brand): add Branch.brand field`,
  `fix(web): …`, `i18n(mobile): …`.
- Commit or push only when the owner asks; branch off `main` first.
- Secrets live in env vars (see `/.env.example`); never commit real values.
